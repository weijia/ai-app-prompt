# 活动邀请函页面

> 倒计时 + 日程 + 报名名单 · 难度：★★☆ · 约 3 分钟

## 适用场景

婚礼、生日聚会、公司年会、线下分享会的邀请页，带倒计时和报名。

## 占位符说明

| 占位符 | 含义 | 示例 |
| --- | --- | --- |
| `{{活动名称}}` | 叫什么 | 「小满生日烧烤派对」 |
| `{{活动时间}}` | 什么时候 | 「2026-10-01 18:00」 |
| `{{活动地点}}` | 在哪 | 「城市露营地·朝阳店」 |

## 提示词（中文版）

````text
请生成一个「活动邀请函」单文件网页应用。

【配置】
活动名称：{{活动名称}}
活动时间：{{活动时间}}
活动地点：{{活动地点}}

【功能要求】
1. 首屏：活动名称大字、一句邀请语、日期时间、地点、封面（用纯 CSS 渐变 + 几何元素绘制的氛围背景，不使用外部图片）。
2. 倒计时：距活动开始的实时倒计时（天/时/分/秒四个卡片），基于 Date.now() 时间戳计算避免后台降频误差；活动已开始时切换为「活动进行中」，已结束则显示「活动已圆满结束」并把页面主色调转为灰色。
3. 日程安排：时间轴列表（每项含时间、环节名称、说明），用 CSS 竖线连起来，支持增删条目（编辑模式）。
4. 报名表单：姓名、人数（1-10）、是否参加、忌口/备注；提交后写入 localStorage 并在下方名单区显示（头像用首字母色块，显示姓名后保留隐私：姓名中间字用 * 代替，如「王*明」）。
5. 名单统计：已报名人数、总人数是否达到上限（可在设置里设人数上限，达到后提示候补）。
6. 添加到日历：提供「添加到日历」按钮，点击下载 .ics 文件（Blob 生成，含 VEVENT 的正确字段 DTSTART/DTEND/SUMMARY/LOCATION，注意 UTC 时间格式处理）。
7. 分享：导出只读版 HTML（把活动内容与报名数据快照内联，页面只读）；提供复制邀请文案按钮（生成一段可直接粘到微信的文案）。

【依赖策略】
纯原生 JavaScript + CSS + Blob，零第三方库，零 CDN，零外部图片。

【交付格式】
只输出一个完整 index.html，HTML/CSS/JS 全部内联，不用 npm 与构建工具。
回复结构：一句话说明 → 唯一的 ```html 完整代码块（禁止省略号）→ 3 行使用说明。

【工程要求】
1. 界面全中文，移动端优先响应式（含 viewport meta），375px 宽下倒计时四个卡片两行两列排列，报名按钮吸底。
2. 数据用 localStorage 持久化，key 前缀 "invite-"，提供「导出 JSON / 导入 JSON」。
3. 处理：姓名为空的校验、重复报名的识别（同名提示覆盖）、人数超限的候补提示、时间已过状态下的报名禁用。
4. 视觉：氛围感优先——根据活动性质选择合适色调（生日暖橙、婚礼柔粉、年会深蓝），封面有细微动效（缓慢漂浮的光斑，CSS keyframes），prefers-color-scheme 暗色模式，尊重 prefers-reduced-motion。
5. 代码总量建议控制在 650 行左右；功能完整性优先于行数——不得为压缩行数而省略功能或用省略号代替代码，超出时只精简注释与冗余写法。倒计时与 .ics 生成部分加中文注释。
````

## Prompt (English Version)

````text
Generate a single-file "Event Invitation" web app.

[CONFIG]
Event name: {{NAME}}
Event time: {{TIME}}
Venue: {{VENUE}}

[FEATURES]
1. Hero: giant event name, one-line invite message, date & time, venue, and a CSS gradient + geometric ambience cover (no external images).
2. Countdown: live days/hours/minutes/seconds cards computed from Date.now() timestamps so background throttling can't distort them; switch to "Happening now" once started and "Event has ended" (graying the palette) after it finishes.
3. Agenda: timeline list (time, item title, description) connected by a CSS vertical line, editable in edit mode.
4. RSVP form: name, party size (1-10), attending yes/no, dietary notes; submissions persist to localStorage and appear in the guest list below, with initial-letter avatar blocks and partial name masking for privacy (e.g. "J*n D**").
5. Guest stats: headcount so far and whether the configurable capacity is reached (shows waitlist status when full).
6. Add to calendar: download a generated .ics via Blob with correct VEVENT fields DTSTART/DTEND/SUMMARY/LOCATION and proper UTC formatting.
7. Sharing: export a read-only HTML snapshot with content and guest data inlined; plus a "Copy invite text" button producing a paste-ready message.

[DEPENDENCIES]
Vanilla JS + CSS + Blob. Zero libraries, zero CDN, zero external images.

[DELIVERY]
One complete index.html, all inline. No npm, no build tools.
Reply: one-line summary -> exactly ONE ```html full block (no ellipsis) -> 3 usage lines.

[QUALITY]
1. English UI, mobile-first responsive with viewport meta; at 375px countdown cards go 2x2 and the RSVP button sticks to the bottom.
2. localStorage with key prefix "invite-"; Export/Import JSON.
3. Validate empty names, detect duplicate RSVPs (ask to overwrite), handle waitlist when full, and disable RSVP after the event has passed.
4. Ambience first: pick a palette suited to the occasion (birthday warm orange, wedding soft pink, gala deep blue), subtle floating light spots via CSS keyframes, prefers-color-scheme dark mode, respect prefers-reduced-motion.
5. Aim for about 650 lines; completeness outranks length — never drop features or use ellipsis to save lines; if it runs over, trim comments and redundancy only. Comment the countdown and .ics generation.
````

## 生成后自检清单

- [ ] 倒计时每秒更新且切后台再回来依然准确
- [ ] 活动已过时时报名被禁用且文案正确
- [ ] 下载的 .ics 能被手机日历正确识别
- [ ] 重复同名报名有明显提示
- [ ] 隐私打码生效（名单里看不到全名）
