# 2048

> 滑动合并 + 合并动画 + 撤销一步 · 难度：★★☆ · 约 3 分钟

## 占位符说明

| 占位符 | 含义 | 示例 |
| --- | --- | --- |
| `{{棋盘大小}}` | 4x4 还是 5x5 | 「4 x 4」 |
| `{{额外功能}}` | 想要什么 | 「撤销一步、历史最高分、动画」 |

## 提示词（中文版）

````text
请生成一个「2048」单文件网页游戏。

【配置】
棋盘大小：{{棋盘大小}}
想要的额外功能：{{额外功能}}

【功能要求】
1. 4x4（或 N x N）棋盘，初始随机生成 2 个方块（90% 概率为 2，10% 为 4）。
2. 操控：方向键 ↑↓←→、WASD、手机滑动（touch 事件计算方向阈值 ≥ 24px）、屏幕虚拟方向按钮。
3. 合并规则（必须严格正确）：
   - 每行朝移动方向压缩到底
   - 相邻相同数字合并，每个方块在一次移动中只能合并一次（合并后该方块本轮不再参与后续合并）
   - 合并顺序统一从「移动方向的那一端」开始处理，避免方向不同导致结果不一致
   - 只有当棋盘状态真正发生变化时才生成新方块（无效移动不生成）
4. 动画：方块移动与新生成使用 CSS transform 过渡（建议用绝对定位的 tile 层实现位移动画，而不是简单的整格重绘），合并时有一次轻微放大反馈；动画时长 120-160ms，动画期间不接受新输入。
5. 撤销：保存上一步棋盘快照（只保留 1 步），点击撤销恢复；每局限用次数可选（默认无限但每次都会置灰标识）。
6. 计分：合并所得数值累加到分数；最高分 localStorage 保存；显示当前分与本局增量、历史最高。
7. 结束判定：棋盘填满且四个方向都无法合并时游戏结束，显示「游戏结束」浮层与再来一局；达成 2048 时弹出祝贺但仍可继续玩。
8. 视觉：数字方块按数值使用不同底色（参照经典 2048 的暖色梯度），文字大小随位数自适应（4 位及以上缩小字号）。

【依赖策略】
纯原生 JavaScript + CSS transform。零第三方库，零 CDN。

【交付格式】
只输出一个完整 index.html，HTML/CSS/JS 全部内联，不用 npm 与构建工具。
回复结构：一句话说明 → 唯一的 ```html 完整代码块（禁止省略号）→ 3 行操作说明。

【工程要求】
1. 界面全中文，移动端优先响应式（含 viewport meta）；375px 宽棋盘占屏幕宽度 92% 且保持正方形，棋盘区域 touch-action: none 防止页面跟随滚动。
2. 数据用 localStorage 持久化，key 前缀 "game2048-"（保存当前局面与最高分，刷新可续玩）。
3. 处理：动画未结束时的输入丢弃（不是排队积压）、非法手势忽略、localStorage 不可用时降级为纯内存游戏并提示。
4. 视觉：现代简洁、圆角方块、暖色配色、顶部显示目标 2048 与进度提示、prefers-color-scheme 暗色模式、尊重 prefers-reduced-motion（关闭过渡但保留逻辑）。
5. 代码总量建议控制在 600 行左右；功能完整性优先于行数——不得为压缩行数而省略功能或用省略号代替代码，超出时只精简注释与冗余写法。合并算法部分加详细中文注释。
````

## 生成后自检清单

- [ ] `4 4 8 0` 向左滑得到 `8 8 0 0` 而不是 `16 0 0 0`
- [ ] 一次移动中每个方块最多合并一次
- [ ] 无效移动不生成新方块
- [ ] 动画播放中狂按方向键不会错乱
- [ ] 刷新页面能续玩上次局面

## 常用追问

1. 「加 5x5 和 6x6 棋盘切换」
2. 「加每步回退完整历史（不限步）」
3. 「改成六边形变体玩法」—— 若太复杂请明确提示不可行并给出替代方案
