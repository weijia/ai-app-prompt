# 2048

> 滑动合并 + 合并动画 + 撤销一步 · 难度：★★☆ · 约 3 分钟

## 占位符说明

| 占位符 | 含义 | 示例 |
| --- | --- | --- |
| `{{棋盘大小}}` | 4x4 还是 5x5 | 「4 x 4」 |
| `{{额外功能}}` | 想要什么 | 「撤销一步、历史最高分、动画」 |

## 提示词（中文版）

````text
请生成一个「2048」单文件网页游戏。

【配置】
棋盘大小：{{棋盘大小}}
想要的额外功能：{{额外功能}}

【功能要求】
1. 4x4（或 N x N）棋盘，初始随机生成 2 个方块（90% 概率为 2，10% 为 4）。
2. 操控：方向键 ↑↓←→、WASD、手机滑动（touch 事件计算方向阈值 ≥ 24px）、屏幕虚拟方向按钮。
3. 合并规则（必须严格正确）：
   - 每行朝移动方向压缩到底
   - 相邻相同数字合并，每个方块在一次移动中只能合并一次（合并后该方块本轮不再参与后续合并）
   - 合并顺序统一从「移动方向的那一端」开始处理，避免方向不同导致结果不一致
   - 只有当棋盘状态真正发生变化时才生成新方块（无效移动不生成）
4. 动画：方块移动与新生成使用 CSS transform 过渡（建议用绝对定位的 tile 层实现位移动画，而不是简单的整格重绘），合并时有一次轻微放大反馈；动画时长 120-160ms，动画期间不接受新输入。
5. 撤销：保存上一步棋盘快照（只保留 1 步），点击撤销恢复；每局限用次数可选（默认无限但每次都会置灰标识）。
6. 计分：合并所得数值累加到分数；最高分 localStorage 保存；显示当前分与本局增量、历史最高。
7. 结束判定：棋盘填满且四个方向都无法合并时游戏结束，显示「游戏结束」浮层与再来一局；达成 2048 时弹出祝贺但仍可继续玩。
8. 视觉：数字方块按数值使用不同底色（参照经典 2048 的暖色梯度），文字大小随位数自适应（4 位及以上缩小字号）。

【依赖策略】
纯原生 JavaScript + CSS transform。零第三方库，零 CDN。

【交付格式】
只输出一个完整 index.html，HTML/CSS/JS 全部内联，不用 npm 与构建工具。
回复结构：一句话说明 → 唯一的 ```html 完整代码块（禁止省略号）→ 3 行操作说明。

【工程要求】
1. 界面全中文，移动端优先响应式（含 viewport meta）；375px 宽棋盘占屏幕宽度 92% 且保持正方形，棋盘区域 touch-action: none 防止页面跟随滚动。
2. 数据用 localStorage 持久化，key 前缀 "game2048-"（保存当前局面与最高分，刷新可续玩）。
3. 处理：动画未结束时的输入丢弃（不是排队积压）、非法手势忽略、localStorage 不可用时降级为纯内存游戏并提示。
4. 视觉：现代简洁、圆角方块、暖色配色、顶部显示目标 2048 与进度提示、prefers-color-scheme 暗色模式、尊重 prefers-reduced-motion（关闭过渡但保留逻辑）。
5. 代码行数控制在 600 行以内，合并算法部分加详细中文注释。
````

## Prompt (English Version)

````text
Generate a single-file "2048" web game.

[CONFIG]
Board size: {{SIZE}}
Extra features wanted: {{EXTRAS}}

[FEATURES]
1. 4x4 (or N x N) board starting with two random tiles (90% a 2, 10% a 4).
2. Controls: arrow keys, WASD, touch swipe (touch events with a >= 24px threshold), and an on-screen D-pad.
3. Merge rules — must be exactly right:
   - slide each row/column fully toward the move direction
   - equal adjacent tiles merge, and each tile merges at most once per move (a merged tile can't merge again in the same move)
   - process from the end the tiles move toward, so direction never changes the outcome
   - spawn a new tile only when the board actually changed (no-op moves spawn nothing)
4. Animation: move and spawn tiles with CSS transform transitions (use an absolutely positioned tile layer for sliding rather than redrawing cells), plus a slight scale pop on merge; 120-160ms duration, and ignore input while animating.
5. Undo: keep one previous board snapshot and restore it on tap; optionally limit uses (default unlimited, with a dimmed indicator when used).
6. Scoring: add each merged value to the score; keep a localStorage high score; show current score, this-run gain, and best.
7. Game over when the board is full and no direction can merge — overlay with Play again; reaching 2048 shows a congratulation but allows continuing.
8. Visuals: classic 2048 warm color ramp by value, font size shrinking for 4+ digit tiles.

[DEPENDENCIES]
Vanilla JS + CSS transform. Zero libraries, zero CDN.

[DELIVERY]
One complete index.html, all inline. No npm, no build tools.
Reply: one-line summary -> exactly ONE ```html full block (no ellipsis) -> 3 control-hint lines.

[QUALITY]
1. English UI, mobile-first responsive with viewport meta; at 375px the board takes 92% of screen width and stays square, with touch-action: none on the board area to prevent page scrolling.
2. localStorage with key prefix "game2048-" (persist board and best score so a refresh resumes the game).
3. Drop input during animations rather than queueing it, ignore invalid gestures, and degrade to in-memory play with a notice if localStorage is unavailable.
4. Modern clean visuals: rounded tiles, warm palette, progress hint toward 2048 up top, prefers-color-scheme dark mode, respect prefers-reduced-motion (disable transitions, keep logic).
5. Keep under 600 lines; comment the merge algorithm thoroughly.
````

## 生成后自检清单

- [ ] `4 4 8 0` 向左滑得到 `8 8 0 0` 而不是 `16 0 0 0`
- [ ] 一次移动中每个方块最多合并一次
- [ ] 无效移动不生成新方块
- [ ] 动画播放中狂按方向键不会错乱
- [ ] 刷新页面能续玩上次局面
