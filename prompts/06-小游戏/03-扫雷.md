# 扫雷

> 三档难度 + 首次点击必安全 + 旗标与计时 · 难度：★★★ · 约 3 分钟

## 占位符说明

| 占位符 | 含义 | 示例 |
| --- | --- | --- |
| `{{难度档位}}` | 三档怎么设 | 「初级 9x9/10 雷，中级 16x16/40 雷，高级 30x16/99 雷」 |
| `{{操作偏好}}` | 左键右鍵怎么分配 | 「左键翻开，右键标旗，双击数字自动展开」 |

## 提示词（中文版）

````text
请生成一个「扫雷」单文件网页游戏。

【配置】
难度档位：{{难度档位}}
操作偏好：{{操作偏好}}

【功能要求】
1. 三档难度切换 + 自定义行列与雷数（雷数不得超过格子数 - 9）。
2. 首次点击必安全：雷区在用户第一次点击之后才生成，且保证首次点击的格子及其 8 邻域都不是雷（用「把该格及邻域排除后再随机布雷」的方式实现）。
3. 核心规则必须正确：
   - 点击数字格且周围旗数等于该数字时，双击（或 alt+点击）自动展开周围未标记的格子（chord / 连开）
   - 周围雷数计数含对角线共 8 个邻居
   - 递归展开：点到周围雷数为 0 的格子时递归展开其邻居（注意用栈/队列实现，不要用可能爆栈的深递归，大棋盘尤其重要）
4. 交互：左键翻开、右键（contextmenu 需 preventDefault）标记旗子 → 问号 → 空白循环标记；首次点击开始计时；剩余雷数 = 总雷数 - 已插旗数（可为负，显示负数即可）。
5. 触屏适配：短按视为翻开，长按 400ms 视为插旗（长按期间显示提示并可取消），并提供「插旗模式」开关按钮作为备选操作方式。
6. 胜负判定：翻开雷则失败（展示所有雷的位置，误插的旗画叉，踩中的雷高亮红色）；所有非雷格子都被翻开则胜利，记录用时到排行榜（按难度分别保存 TOP 5）。
7. 视觉：格子凹凸感（未翻开有立体边框，翻开后扁平），数字 1-8 使用经典配色（1蓝2绿3红4深蓝5棕6青7黑8灰），雷用内联 SVG 或 emoji 绘制，胜利/失败时有顶部横幅反馈。

【依赖策略】
纯原生 JavaScript + CSS Grid + 内联 SVG/emoji。零第三方库，零 CDN。

【交付格式】
只输出一个完整 index.html，HTML/CSS/JS 全部内联，不用 npm 与构建工具。
回复结构：一句话说明 → 唯一的 ```html 完整代码块（禁止省略号）→ 3 行操作说明。

【工程要求】
1. 界面全中文，移动端优先响应式（含 viewport meta）；棋盘超出屏宽时允许横向滚动并保持格子不小于 32px；棋盘区域 touch-action: manipulation 并禁用双击缩放。
2. 数据用 localStorage 持久化，key 前缀 "minesweeper-"（保存难度偏好与排行榜），当前对局可保存以便刷新续玩。
3. 处理：游戏结束后禁止继续操作、计时上限处理（超过 999 秒显示 999）、自定义参数的非法值校验。
4. 视觉：现代简洁但保留经典手感、深色数字高对比、状态栏显示剩余雷数与计时、prefers-color-scheme 暗色模式。
5. 递归展开必须用迭代实现，并在代码注释里说明原因。
6. 代码行数控制在 650 行以内，布雷与展开逻辑加中文注释。
````

## Prompt (English Version)

````text
Generate a single-file "Minesweeper" web game.

[CONFIG]
Difficulty tiers: {{TIERS}}
Controls: {{CONTROLS}}

[FEATURES]
1. Three difficulty tiers plus custom rows/columns/mines (mines must not exceed cells - 9).
2. Always-safe first click: generate mines only after the first click, excluding that cell and its 8 neighbors before placing mines at random.
3. Core rules must be exact:
   - chording: clicking (or alt+clicking) a revealed number whose flag count equals its value reveals all unflagged neighbors
   - neighbor counts include diagonals, 8 total
   - zero-count cells flood-reveal their neighbors, implemented with an explicit stack/queue instead of deep recursion, which can blow the stack on large boards
4. Interaction: left click reveals; right click (preventDefault on contextmenu) cycles flag -> question -> empty; the timer starts on the first reveal; remaining mines = total - flags placed (negative is fine, show it).
5. Touch adaptation: tap reveals, 400ms long-press flags (with cancel feedback during the press), plus a "flag mode" toggle button as an alternative.
6. Win/lose: revealing a mine loses — reveal every mine, cross out wrong flags and highlight the triggered mine in red; revealing all non-mine cells wins, recording the time to a per-difficulty TOP 5 leaderboard.
7. Visuals: beveled unopened cells vs flat revealed ones, classic number colors (1 blue, 2 green, 3 red, 4 navy, 5 maroon, 6 teal, 7 black, 8 gray), mines drawn with inline SVG or emoji, and a top banner on win/lose.

[DEPENDENCIES]
Vanilla JS + CSS Grid + inline SVG/emoji. Zero libraries, zero CDN.

[DELIVERY]
One complete index.html, all inline. No npm, no build tools.
Reply: one-line summary -> exactly ONE ```html full block (no ellipsis) -> 3 control-hint lines.

[QUALITY]
1. English UI, mobile-first responsive with viewport meta; when the board is wider than the screen allow horizontal scrolling with cells at least 32px; set touch-action: manipulation and disable double-tap zoom on the board.
2. localStorage with key prefix "minesweeper-" (difficulty preference and leaderboards); persist the running game so a refresh resumes it.
3. Lock input after the game ends, cap the timer display at 999, and validate custom parameters.
4. Modern clean look preserving classic feel, high-contrast numbers, a status bar with remaining mines and time, prefers-color-scheme dark mode.
5. Flood reveal must be iterative, with a comment explaining why.
6. Keep under 650 lines; comment mine placement and reveal logic.
````
