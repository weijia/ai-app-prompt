# 五子棋人机对战

> 15x15 棋盘 + 启发式 AI + 悔棋 + 胜负判定 · 难度：★★★ · 约 3 分钟

## 占位符说明

| 占位符 | 含义 | 示例 |
| --- | --- | --- |
| `{{棋盘规格}}` | 几路棋 | 「15 x 15」 |
| `{{AI 强度}}` | 电脑多强 | 「中等：能防守活三，算 2 层」 |

## 提示词（中文版）

````text
请生成一个「五子棋人机对战」单文件网页游戏。

【配置】
棋盘规格：{{棋盘规格}}
AI 强度：{{AI 强度}}

【功能要求】
1. 棋盘：Canvas 或 CSS Grid 绘制 15x15（按 {{棋盘规格}}）棋盘，含星位点标记；玩家执黑先行，AI 执白。
2. 落子：点击/触摸交叉点落子；已有棋子处不可落；AI 思考期间禁止落子并显示「电脑思考中…」；提供最后落子标记（小方框）便于看清 AI 走了哪。
3. 胜负判定（必须准确）：每次落子后只检查以该子为中心的四条方向线（横、竖、两条斜线），统计同色连续棋子数 ≥ 5 即胜；不要用全盘扫描避免性能问题也不要误判超过 5 连（六连也算赢）。
4. AI 算法（启发式打分，明确写在代码里）：
   - 对每个空位计算进攻分与防守分
   - 棋型识别：连五(100000)、活四(10000)、冲四(1000)、活三(1000)、眠三(100)、活二(100)、眠二(10)
   - 最终得分 = 进攻分 + 防守分 * 0.8（防守权重略低但要能拦住活三与冲四）
   - 必胜/必防优先级：自己能成五直接落；对手能成五必须先堵；自己能成活四优先；对手活四必堵
   - 取最高分随机其一（同分时随机，避免每局完全一样）
   - 性能：只在已有棋子周围 2 格范围内的空位里搜索，避免遍历全盘
5. 悔棋：撤销「玩家一步 + AI 一步」（若 AI 尚未落则只撤一步），维护完整棋步栈，可连续悔到开局；悔棋后重算胜负状态。
6. 其他：重开按钮、先后手切换（要不要让玩家执白）、AI 思考延迟 300-600ms（用 setTimeout 包裹以免界面假死并显示思考提示）。
7. 视觉：木纹底色（CSS 渐变模拟，不外链图片）、棋子带轻微径向渐变立体感、落子有短促动画、胜利时高亮获胜五子连线（画一条半透明白线）。

【依赖策略】
纯原生 JavaScript + Canvas 2D（或 CSS Grid）。零第三方库，零 CDN。

【交付格式】
只输出一个完整 index.html，HTML/CSS/JS 全部内联，不用 npm 与构建工具。
回复结构：一句话说明 → 唯一的 ```html 完整代码块（禁止省略号）→ 3 行操作说明。

【工程要求】
1. 界面全中文，移动端优先响应式（含 viewport meta）；375px 宽下棋盘占屏幕宽度 96% 且正方形，交叉点点击区域要比视觉棋子大以便点准。
2. 棋局用 localStorage 持久化，key 前缀 "gomoku-"（保存未完成对局，刷新可续下）。
3. 处理：平局（棋盘填满未分胜负）判定、AI 无子可下时的处理、悔棋到空棋盘时不报错。
4. 绘制：高 DPI 屏适配（canvas.width = CSS 尺寸 * devicePixelRatio，再用 scale 绘制，避免模糊）。
5. 代码行数控制在 700 行以内，胜负判定与 AI 打分部分加详细中文注释。
````

## Prompt (English Version)

````text
Generate a single-file "Gomoku vs AI" web game.

[CONFIG]
Board: {{SIZE}}
AI strength: {{LEVEL}}

[FEATURES]
1. Board: draw 15x15 (per {{SIZE}}) on Canvas or CSS Grid with star points. Player is black and moves first; AI is white.
2. Placing stones: click/tap an intersection; occupied points reject the move; block input while the AI thinks and show "Computer thinking..."; mark the last move with a small square so it's obvious what the AI played.
3. Win detection — must be exact: after each move check only the four lines through that stone (horizontal, vertical, two diagonals) and count consecutive same-color stones; >= 5 wins. Do not scan the whole board every time, and do not mis-handle overlines (six in a row also wins).
4. Heuristic AI, written explicitly in code:
   - score every empty cell for offense and defense
   - recognize patterns: five 100000, open four 10000, four 1000, open three 1000, closed three 100, open two 100, closed two 10
   - final score = offense + defense * 0.8 (defense weighted slightly lower, but it must block open threes and fours)
   - hard priorities: complete your own five first; block the opponent's five immediately; prefer making an open four; always block the opponent's open four
   - pick randomly among the top-scoring cells so games differ
   - performance: only search empty cells within 2 cells of an existing stone instead of the whole board
5. Undo: revert one player move plus one AI move (or just one if the AI hasn't moved), backed by a full move stack that can unwind to the opening; recompute win state after undo.
6. Extras: restart button, side swap (player plays white), and a 300-600ms AI think delay wrapped in setTimeout so the UI never freezes while showing the thinking indicator.
7. Visuals: wood-grain board via CSS gradient (no external image), stones with subtle radial shading, brief placement animation, and a translucent line highlighting the winning five on victory.

[DEPENDENCIES]
Vanilla JS + Canvas 2D (or CSS Grid). Zero libraries, zero CDN.

[DELIVERY]
One complete index.html, all inline. No npm, no build tools.
Reply: one-line summary -> exactly ONE ```html full block (no ellipsis) -> 3 control-hint lines.

[QUALITY]
1. English UI, mobile-first responsive with viewport meta; at 375px the board takes 96% of width and stays square, with tap targets larger than the drawn stones for accuracy.
2. localStorage with key prefix "gomoku-" so an unfinished game can continue after refresh.
3. Handle draws (full board, no winner), the case where the AI has no legal move, and undoing down to an empty board without errors.
4. HiDPI support: set canvas.width to CSS size * devicePixelRatio and scale the context so lines stay crisp.
5. Keep under 700 lines; comment win detection and AI scoring thoroughly.
````
