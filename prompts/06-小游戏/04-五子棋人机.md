# 五子棋人机对战

> 15x15 棋盘 + 启发式 AI + 悔棋 + 胜负判定 · 难度：★★★ · 约 3 分钟

## 占位符说明

| 占位符 | 含义 | 示例 |
| --- | --- | --- |
| `{{棋盘规格}}` | 几路棋 | 「15 x 15」 |
| `{{AI 强度}}` | 电脑多强 | 「中等：能防守活三，算 2 层」 |

## 提示词（中文版）

````text
请生成一个「五子棋人机对战」单文件网页游戏。

【配置】
棋盘规格：{{棋盘规格}}
AI 强度：{{AI 强度}}

【功能要求】
1. 棋盘：Canvas 或 CSS Grid 绘制 15x15（按 {{棋盘规格}}）棋盘，含星位点标记；玩家执黑先行，AI 执白。
2. 落子：点击/触摸交叉点落子；已有棋子处不可落；AI 思考期间禁止落子并显示「电脑思考中…」；提供最后落子标记（小方框）便于看清 AI 走了哪。
3. 胜负判定（必须准确）：每次落子后只检查以该子为中心的四条方向线（横、竖、两条斜线），统计同色连续棋子数 ≥ 5 即胜；不要用全盘扫描避免性能问题也不要误判超过 5 连（六连也算赢）。
   具体写法要求：
   - 判定函数入口必须防御：`if (越界 || board[y][x] !== color) return false;`
     实测踩坑：缺少这行时，若误把空点或非本方色的坐标传进来，左右分别延伸会各自数到 >= 5，导致「空坐标也被判胜」。
   - 计数方式为「从落子点出发向该方向的两端逐格延伸，一旦遇到非同色立即停止」，遇到边界同样停止；两侧数量相加 +1 即总连数。
   - 需要用这几组用例自测：横向五连胜 / 六连也胜 / 四连不胜 / 主对角线胜 / 副对角线胜 / 中间被对方子拦断（如 B B W B B B）不胜 / 传入空点不胜。
4. AI 算法（启发式打分，明确写在代码里）：
   - 对每个空位计算进攻分与防守分
   - 棋型识别：连五(100000)、活四(10000)、冲四(1000)、活三(1000)、眠三(100)、活二(100)、眠二(10)
   - 最终得分 = 进攻分 + 防守分 * 0.8（防守权重略低但要能拦住活三与冲四）
   - 必胜/必防优先级：自己能成五直接落；对手能成五必须先堵；自己能成活四优先；对手活四必堵
   - 取最高分随机其一（同分时随机，避免每局完全一样）
   - 性能：只在已有棋子周围 2 格范围内的空位里搜索，避免遍历全盘
5. 悔棋：撤销「玩家一步 + AI 一步」（若 AI 尚未落则只撤一步），维护完整棋步栈，可连续悔到开局；悔棋后重算胜负状态。
6. 其他：重开按钮、先后手切换（要不要让玩家执白）、AI 思考延迟 300-600ms（用 setTimeout 包裹以免界面假死并显示思考提示）。
7. 视觉：木纹底色（CSS 渐变模拟，不外链图片）、棋子带轻微径向渐变立体感、落子有短促动画、胜利时高亮获胜五子连线（画一条半透明白线）。

【依赖策略】
纯原生 JavaScript + Canvas 2D（或 CSS Grid）。零第三方库，零 CDN。

【交付格式】
只输出一个完整 index.html，HTML/CSS/JS 全部内联，不用 npm 与构建工具。
回复结构：一句话说明 → 唯一的 ```html 完整代码块（禁止省略号）→ 3 行操作说明。

【工程要求】
1. 界面全中文，移动端优先响应式（含 viewport meta）；375px 宽下棋盘占屏幕宽度 96% 且正方形，交叉点点击区域要比视觉棋子大以便点准。
2. 棋局用 localStorage 持久化，key 前缀 "gomoku-"（保存未完成对局，刷新可续下）。
3. 处理：平局（棋盘填满未分胜负）判定、AI 无子可下时的处理、悔棋到空棋盘时不报错。
4. 绘制：高 DPI 屏适配（canvas.width = CSS 尺寸 * devicePixelRatio，再用 scale 绘制，避免模糊）。
5. 代码总量建议控制在 700 行左右；功能完整性优先于行数——不得为压缩行数而省略功能或用省略号代替代码，超出时只精简注释与冗余写法。胜负判定与 AI 打分部分加详细中文注释。
````
