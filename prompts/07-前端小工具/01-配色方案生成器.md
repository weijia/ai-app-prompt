# 配色方案生成器

> 主色生成色板 + 对比度校验 + CSS 变量导出 · 难度：★★☆ · 约 3 分钟

## 占位符说明

| 占位符 | 含义 | 示例 |
| --- | --- | --- |
| `{{用途}}` | 配色的目的 | 「给公司的后台管理系统定主色」 |
| `{{必备模式}}` | 需要哪些 palette | 「互补色、邻近色、同色系深浅 10 阶」 |

## 提示词（中文版）

````text
请生成一个「配色方案生成器」单文件网页应用，所有颜色计算在前端本地完成。

【配置】
用途：{{用途}}
需要的配色模式：{{必备模式}}

【功能要求】
1. 输入方式：原生 color input 选色、HEX 输入框（支持 #abc 简写自动补全）、HSL 三个滑杆（色相/饱和度/明度），三者双向联动。
2. 配色规则（算法写在代码里，基于 HSL 空间计算，不要用 RGB 加减）：
   - 互补色：色相 +180°
   - 三角配色：色相 +120°、+240°
   - 邻近配色：色相 ±30°
   - 分裂互补：色相 +150°、+210°
   - 同色系 10 阶：固定色相，明度从 95% 到 15% 均匀取样（用于生成 Tailwind 风格的 50-900 色阶）
3. 色阶展示：每种模式渲染一排色卡，每个色块显示 HEX 值，点击即复制到剪贴板并显示 toast；支持切换显示 HEX / RGB / HSL 三种格式。
4. 对比度校验（重要）：用户选择前景色与背景色后，按照 WCAG 2.1 相对亮度公式计算对比度：
   L = 0.2126R + 0.7152G + 0.0722B（其中每个通道先做 sRGB 线性化处理）
   对比度 = (L1 + 0.05) / (L2 + 0.05)
   给出 AA 正常文本(4.5)、AA 大文本(3)、AAA(7) 三个档位的通过/未通过标识与具体数值。
5. 实时预览：在右侧用当前主色渲染一个示例界面片段（导航栏 + 卡片 + 按钮 + 正文），直观看到搭配效果；提供浅色/暗色两种背景预览。
6. 导出：
   - 导出 CSS 变量：`:root { --primary-50: #...; ... }`
   - 导出 Tailwind 配置片段
   - 导出 SCSS 变量
   - 导出 JSON
7. 收藏：把喜欢的配色方案保存到 localStorage，可命名、删除、再次载入。

【依赖策略】
纯原生 JavaScript 实现颜色空间转换（HEX↔RGB↔HSL），零第三方库，零 CDN，零外部图片。

【交付格式】
只输出一个完整 index.html，HTML/CSS/JS 全部内联，不用 npm 与构建工具。
回复结构：一句话说明 → 唯一的 ```html 完整代码块（禁止省略号）→ 3 行使用说明。

【工程要求】
1. 界面全中文，移动端优先响应式（含 viewport meta），375px 宽下色卡改为两列网格。
2. 数据用 localStorage 持久化，key 前缀 "palette-"，提供「导出 JSON / 导入 JSON」。
3. 处理：非法 HEX 输入的行内提示与自动纠正（例如漏写 # 时自动补上）、复制失败降级方案、空收藏列表引导。
4. 视觉：界面本身要好看——卡片化分区、色卡圆角小阴影、hover 显示复制图标、prefers-color-scheme 暗色模式。
5. 无障碍：色卡的可读性靠文字标签保证，不要只依赖颜色传达信息。
6. 代码行数控制在 600 行以内，颜色转换与对比度公式部分加中文注释。
````

## Prompt (English Version)

````text
Generate a single-file "Color Palette Generator" web app. All color math happens locally in the browser.

[CONFIG]
Purpose: {{PURPOSE}}
Required palette modes: {{MODES}}

[FEATURES]
1. Inputs: a native color picker, a HEX field (auto-expand shorthand like #abc), and three HSL sliders (hue/saturation/lightness), all two-way synced.
2. Palette rules implemented in code using HSL math (never naive RGB arithmetic):
   - complementary: hue + 180
   - triadic: hue + 120 and + 240
   - analogous: hue ± 30
   - split complementary: hue + 150 and + 210
   - monochrome ramp: same hue, lightness sampled from 95% down to 15% in 10 steps (Tailwind-style 50-900)
3. Swatch display: one row of cards per mode showing HEX values; clicking copies to the clipboard with a toast; toggle the label format between HEX / RGB / HSL.
4. Contrast checker (important): given foreground and background, compute the WCAG 2.1 contrast ratio:
   L = 0.2126R + 0.7152G + 0.0722B with sRGB linearization per channel
   ratio = (L1 + 0.05) / (L2 + 0.05)
   Mark pass/fail for AA normal text (4.5), AA large text (3) and AAA (7) with the actual number.
5. Live preview: render a sample UI slice (nav bar, card, button, body text) using the current primary color, switchable between light and dark backgrounds.
6. Export: CSS variables `:root { --primary-50: #...; ... }`, a Tailwind config snippet, SCSS variables, and JSON.
7. Favorites: save palettes to localStorage with names, delete and reload them.

[DEPENDENCIES]
Vanilla JS with hand-written HEX<->RGB<->HSL conversions. Zero libraries, zero CDN, no external images.

[DELIVERY]
One complete index.html, all inline. No npm, no build tools.
Reply: one-line summary -> exactly ONE ```html full block (no ellipsis) -> 3 usage lines.

[QUALITY]
1. English UI, mobile-first responsive with viewport meta; swatches go two-up at 375px.
2. localStorage with key prefix "palette-"; Export/Import JSON.
3. Inline validation and auto-correction for HEX input (prepend # when missing), a clipboard fallback, and empty-favorites guidance.
4. The UI itself should look good: card-based sections, rounded swatches with subtle shadow, copy icon on hover, prefers-color-scheme dark mode.
5. Accessibility: never rely on color alone — always pair swatches with text labels.
6. Keep under 600 lines; comment the color conversion and contrast math.
````
