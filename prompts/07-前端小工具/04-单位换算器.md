# 单位换算器

> 多类别换算 + 常用收藏 + 汇率手动兜底 · 难度：★☆☆ · 约 2 分钟

## 占位符说明

| 占位符 | 含义 | 示例 |
| --- | --- | --- |
| `{{常换算类别}}` | 常用哪些 | 「长度、重量、温度、数据存储、汇率」 |
| `{{默认精度}}` | 保留几位小数 | 「4」 |

## 提示词（中文版）

````text
请生成一个「单位换算器」单文件网页应用。

【配置】
我常用的换算类别：{{常换算类别}}
默认结果精度：{{默认精度}} 位小数

【功能要求】
1. 分类切换：长度、重量/质量、温度、面积、体积、时间、速度、数据存储（含 1024 与 1000 两套进制，要明确区分 KiB 与 KB）、压力、功率、能量。每类一个标签页或下拉。
2. 换算界面：左侧输入数值 + 单位下拉，右侧显示结果数值 + 单位下拉；双向联动（改任一侧另一侧跟着算）。
3. 换算表必须写死在代码里，以「基准单位 + 系数」的形式组织（例如长度基准为米，1 km = 1000 m），换算统一走「转基准再转目标」，避免 O(n²) 的组合表。
4. 温度换算必须特殊处理（不能只用乘系数）：摄氏/华氏/开尔文/兰氏之间用公式互转（°F = °C × 9/5 + 32，K = °C + 273.15）。
5. 精度处理：浮点数换算后要用 toFixed 与 Number 处理去掉多余的 0，并避免 0.1+0.2 类误差（建议统一乘以 10^n 取整再除）；极大极小数自动切换为科学计数法显示。
6. 常用收藏：可把当前「类别 + 源单位 + 目标单位」组合加入收藏，首页以快捷卡片展示，支持删除排序。
7. 汇率换算：
   - 默认提供手动填写汇率的表单（用户自己输入当前汇率并存localStorage）
   - 可选尝试从一个公开且国内可访问的接口获取；但必须满足：请求失败、超时（3 秒）、返回格式异常时自动降级为手动模式并给出提示条，绝不阻塞页面正常使用
   - 若你判断没有可靠且免费的国内可访问接口，请直接只做手动汇率模式，并在界面上说明原因
8. 参考速查表：每个类别下方显示该单位与其它常用单位的对照（如 1 米 = 3.2808 英尺 = 39.37 英寸）。
9. 复制结果按钮。

【依赖策略】
纯原生 JavaScript，零第三方库，零 CDN。除用户主动触发且可降级的汇率请求外，不做任何网络请求。

【交付格式】
只输出一个完整 index.html，HTML/CSS/JS 全部内联，不用 npm 与构建工具。
回复结构：一句话说明 → 唯一的 ```html 完整代码块（禁止省略号）→ 3 行使用说明。

【工程要求】
1. 界面全中文，移动端优先响应式（含 viewport meta），375px 宽下单列布局、数字输入框使用 inputmode="decimal"。
2. 设置与收藏用 localStorage 持久化，key 前缀 "unit-"。
3. 处理：空输入/非法字符（粘贴的逗号、空格、单位符号要做清洗）、负数的场景提示（如温度为负是合法的，长度为负应提示）、结果为 0 或无穷大的显示处理。
4. 视觉：现代简洁、大号数字显示结果（主色加粗）、分类横向滚动标签、复制反馈、prefers-color-scheme 暗色模式。
5. 代码行数控制在 600 行以内，换算表组织方式与温度特殊处理部分加中文注释。
````

## Prompt (English Version)

````text
Generate a single-file "Unit Converter" web app.

[CONFIG]
Categories I use most: {{CATEGORIES}}
Default result precision: {{PRECISION}} decimals

[FEATURES]
1. Category switching: length, mass, temperature, area, volume, time, speed, data storage (distinguish 1024 vs 1000 systems — KiB vs KB explicitly), pressure, power, energy. Tabs or a dropdown.

3. Hard-code conversion tables organized as "base unit + factor" (e.g. base metre, 1 km = 1000 m) and always convert source -> base -> target instead of maintaining an O(n^2) pair table.
4. Temperature needs formulas, not factors: Celsius / Fahrenheit / Kelvin / Rankine (F = C * 9/5 + 32, K = C + 273.15).
5. Precision: clean up float noise (avoid 0.1 + 0.2 artifacts — scale by 10^n, round, then divide), strip trailing zeros with Number(...) plus toFixed, and switch to scientific notation for extremes.
6. Favorites: save the current "category + from unit + to unit" combo; show them as quick cards on the home screen, reorderable and deletable.
7. Currency:
   - default to a manual exchange-rate form (the user enters the rate, stored in localStorage)
   - optionally try one public China-accessible endpoint, but only if failures, a 3s timeout, or unexpected formats degrade gracefully to manual mode with a banner that never blocks usage
   - if you believe there is no reliable free China-accessible endpoint, implement manual-only and explain why in the UI
8. Quick reference row under each unit (e.g. 1 metre = 3.2808 ft = 39.37 in).
9. Copy-result button.

[DEPENDENCIES]
Vanilla JS only, zero libraries, zero CDN. No network requests other than an optional, fully degradable currency fetch triggered by the user.

[DELIVERY]
One complete index.html, all inline. No npm, no build tools.
Reply: one-line summary -> exactly ONE ```html full block (no ellipsis) -> 3 usage lines.

[QUALITY]
1. English UI, mobile-first responsive with viewport meta; single column at 375px with inputmode="decimal" numeric fields.
2. Persist settings and favorites in localStorage with key prefix "unit-".
3. Sanitize pasted values (strip commas, spaces, unit symbols), warn where negatives are nonsensical (length) while allowing valid ones (temperature), and handle zero/infinite results gracefully.
4. Modern clean visuals: big bold result number in the primary color, horizontally scrolling category tabs, copy feedback, prefers-color-scheme dark mode.
5. Keep under 600 lines; comment how the tables are organized and the special temperature handling.
````
