## 提示词（中文版）

````text
请生成一个「图片压缩工具」单文件网页应用，全部在浏览器本地处理，绝不上传图片。

【配置】
主要使用场景：{{常见场景}}
需要的功能：{{支持功能}}

【功能要求】
1. 导入：点击选择 / 拖拽多张图片到拖放区（dragover/drop 需 preventDefault）/ 粘贴剪贴板图片（paste 事件）；单张最大支持 20MB，超出时提示。
2. 压缩参数面板：
   - 目标大小模式：输入目标 KB，自动二分或等比迭代 quality 逼近目标（迭代次数上限 8 次，避免死循环）
   - 质量滑杆模式：0.1–1.0 手动调节
   - 最大边长限制（等比缩放，如 1920px）
   - 输出格式：JPEG / PNG / WebP（检测 canvas.toDataURL('image/webp') 是否支持，不支持则灰掉该选项）
3. 实时预览：左右并排显示原图与压缩后效果，中间显示「原图 2.3MB → 压缩后 186KB（-92%）」的信息条；压缩后图片不明显时应给出提示。
4. 批量处理：队列式处理多张图片（用 Promise 串行处理并显示进度条与当前第几张），结果列表显示每张文件名、原大小、新大小、压缩率。
5. 下载：单张下载 + 「打包下载全部（逐个下载）」；文件名格式原名_min.jpg。若实现真正的 ZIP 打包太复杂，就逐个触发下载并在页面上说明。
6. 额外工具：简单的居中裁切（1:1、4:3、16:9 三种比例，Canvas drawImage 实现）、旋转 90°、一键重置。

【关键技术点】
- 读取用 FileReader.readAsDataURL，绘制用 Image + Canvas
- 等比缩放计算要保持宽高比，不能拉伸
- 压缩后体积反而变大时应保留原图并提示（尤其 PNG）
- 释放内存：处理完调用 URL.revokeObjectURL 释放 object URL
- 大图处理前给出「处理中」遮罩，避免用户重复点击

【依赖策略】
纯原生 JavaScript + Canvas + FileReader + Blob，零第三方库，零 CDN。

【交付格式】
只输出一个完整 index.html，HTML/CSS/JS 全部内联，不用 npm 与构建工具。
回复结构：一句话说明 → 唯一的 ```html 完整代码块（禁止省略号）→ 3 行使用说明。

【工程要求】
1. 界面全中文，移动端优先响应式（含 viewport meta），375px 宽下预览改为上下排列、按钮最小 44px。
2. 不把图片写入 localStorage（避免爆配额）；仅用 localStorage 保存用户的压缩参数偏好，key 前缀 "imgtool-"。
3. 处理：非图片文件的拒绝提示、处理失败的单张要有错误标记且不影响其他图片、连续点击开始的处理锁。
4. 视觉：现代简洁、拖拽区虚线框 hover 高亮、压缩率用绿色数字突出显示、prefers-color-scheme 暗色模式。
5. 页面上明确注明「图片不会离开你的设备，全部在本地处理」。
6. 代码行数控制在 650 行以内，压缩迭代与 Canvas 绘制部分加中文注释。
````

## Prompt (English Version)

````text
Generate a single-file "Image Compressor" web app. Everything happens locally in the browser — images are never uploaded.

[CONFIG]
Main use case: {{USECASE}}
Required features: {{FEATURES}}

[FEATURES]
1. Import: click to select / drag multiple images into a drop zone (preventDefault on dragover and drop) / paste from the clipboard (paste event). Accept up to 20MB per image and warn past that.
2. Compression controls:
   - target size mode: enter a target KB and iterate quality (binary or proportional search) to converge, capped at 8 iterations to avoid infinite loops
   - quality slider mode: manual 0.1-1.0
   - max edge length with proportional downscaling (e.g. 1920px)
   - output format: JPEG / PNG / WebP (detect whether canvas.toDataURL('image/webp') works, otherwise disable the option)
3. Live preview: original and result side by side with an info bar like "original 2.3MB -> compressed 186KB (-92%)"; warn when compression wouldn't help much.
4. Batch: process queued images serially with Promises, showing a progress bar and current index; the result list shows filename, original size, new size and ratio per image.
5. Download: single download plus "download all" (triggering downloads one by one); filenames follow originalname_min.jpg. If real ZIP packaging is too complex, download individually and say so on the page.
6. Extras: simple centered cropping at 1:1, 4:3 or 16:9 via Canvas drawImage, rotate 90 degrees, and a reset button.

[KEY TECHNIQUES]
- read with FileReader.readAsDataURL, draw with Image + Canvas
- preserve aspect ratio when scaling — never stretch
- if compression makes a file larger, keep the original and notify (common with PNG)
- free memory with URL.revokeObjectURL after processing
- overlay a "processing" state so repeated clicks can't stack work

[DEPENDENCIES]
Vanilla JS + Canvas + FileReader + Blob. Zero libraries, zero CDN.

[DELIVERY]
One complete index.html, all inline. No npm, no build tools.
Reply: one-line summary -> exactly ONE ```html full block (no ellipsis) -> 3 usage lines.

[QUALITY]
1. English UI, mobile-first responsive with viewport meta; previews stack vertically at 375px and buttons are at least 44px.
2. Never store images in localStorage (quota blowout); only persist the user's compression preferences with key prefix "imgtool-".
3. Reject non-image files, mark failed items without blocking the rest, and lock against repeated start clicks.
4. Modern clean visuals: dashed drop zone highlighting on hover, green compression ratio figures, prefers-color-scheme dark mode.
5. State clearly on the page: "Images never leave your device — all processing is local."
6. Keep under 650 lines; comment the compression iteration and Canvas drawing.
````
