## 提示词（中文版）

````text
请生成一个「图片压缩工具」单文件网页应用，全部在浏览器本地处理，绝不上传图片。

【配置】
主要使用场景：{{常见场景}}
需要的功能：{{支持功能}}

【功能要求】
1. 导入：点击选择 / 拖拽多张图片到拖放区（dragover/drop 需 preventDefault）/ 粘贴剪贴板图片（paste 事件）；单张最大支持 20MB，超出时提示。
2. 压缩参数面板：
   - 目标大小模式：输入目标 KB，自动二分或等比迭代 quality 逼近目标（迭代次数上限 8 次，避免死循环）
   - 质量滑杆模式：0.1–1.0 手动调节
   - 最大边长限制（等比缩放，如 1920px）
   - 输出格式：JPEG / PNG / WebP（检测 canvas.toDataURL('image/webp') 是否支持，不支持则灰掉该选项）
3. 实时预览：左右并排显示原图与压缩后效果，中间显示「原图 2.3MB → 压缩后 186KB（-92%）」的信息条；压缩后图片不明显时应给出提示。
4. 批量处理：队列式处理多张图片（用 Promise 串行处理并显示进度条与当前第几张），结果列表显示每张文件名、原大小、新大小、压缩率。
5. 下载：单张下载 + 「打包下载全部（逐个下载）」；文件名格式原名_min.jpg。若实现真正的 ZIP 打包太复杂，就逐个触发下载并在页面上说明。
6. 额外工具：简单的居中裁切（1:1、4:3、16:9 三种比例，Canvas drawImage 实现）、旋转 90°、一键重置。

【关键技术点】
- 读取用 FileReader.readAsDataURL，绘制用 Image + Canvas
- 等比缩放计算要保持宽高比，不能拉伸
- 压缩后体积反而变大时应保留原图并提示（尤其 PNG）
- 释放内存：处理完调用 URL.revokeObjectURL 释放 object URL
- 大图处理前给出「处理中」遮罩，避免用户重复点击

【依赖策略】
纯原生 JavaScript + Canvas + FileReader + Blob，零第三方库，零 CDN。

【交付格式】
只输出一个完整 index.html，HTML/CSS/JS 全部内联，不用 npm 与构建工具。
回复结构：一句话说明 → 唯一的 ```html 完整代码块（禁止省略号）→ 3 行使用说明。

【工程要求】
1. 界面全中文，移动端优先响应式（含 viewport meta），375px 宽下预览改为上下排列、按钮最小 44px。
2. 不把图片写入 localStorage（避免爆配额）；仅用 localStorage 保存用户的压缩参数偏好，key 前缀 "imgtool-"。
3. 处理：非图片文件的拒绝提示、处理失败的单张要有错误标记且不影响其他图片、连续点击开始的处理锁。
4. 视觉：现代简洁、拖拽区虚线框 hover 高亮、压缩率用绿色数字突出显示、prefers-color-scheme 暗色模式。
5. 页面上明确注明「图片不会离开你的设备，全部在本地处理」。
6. 代码总量建议控制在 650 行左右；功能完整性优先于行数——不得为压缩行数而省略功能或用省略号代替代码，超出时只精简注释与冗余写法。压缩迭代与 Canvas 绘制部分加中文注释。
````

## 生成后自检清单

- [ ] 拖入多张图能依次处理完
- [ ] 设定目标 200KB 时能逼近该大小且不死循环

- [ ] PNG 压缩后变大时会提示并保留原图
