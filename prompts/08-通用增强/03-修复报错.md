# 修复报错（追问专用）

> 贴控制台报错让它精准修 bug，而不是整份重来

## 占位符说明

| 占位符 | 含义 | 怎么拿到 |
| --- | --- | --- |
| `{{报错信息}}` | 控制台红字 | F12 → Console，右键 Copy message |
| `{{复现步骤}}` | 怎么触发的 | 「点新建按钮后表格不出现」 |
| `{{期望行为}}` | 希望发生什么 | 「应该新增一行并滚动到它」 |

## 用法

报错信息越完整，修复越准。至少贴：错误类型 + 消息 + 出错文件行号。

## 提示词（中文版）

````text
我的网页出现了一个 bug，请帮我定位并修复，只改出错的部分，不要把整份代码重写一遍。

【错误信息】
{{报错信息}}

【复现步骤】
{{复现步骤}}

【期望行为】
{{期望行为}}

【当前代码】
{{原代码}}

【修复要求】
1. 先做诊断：用 3-5 条说明可能的原因，按可能性从高到低排序，每条指出具体的位置（函数名或大致行号）。
2. 给出最小改动方案：优先局部修改，能用 5 行解决就不要动 50 行。
3. 输出修复后的完整 index.html（必须是完整可运行代码，禁止省略号），并在代码块外列出改动清单：改了哪个函数、为什么这么改。
4. 如果同一个症状有多个可能原因，请额外提供 1-2 个备选修复方案供我在第一种不生效时尝试。
5. 顺手加固：在出错的地方补充必要的防御（判空、try/catch、默认值），但不要为了加防御改动其它无关逻辑。

【约束】
保持 HTML/CSS/JS 内联在单一文件；保持零第三方依赖（或维持原有国内 CDN 依赖）；不改 localStorage 的 key，保证用户已有数据不丢；界面保持中文。

【输出格式】
诊断结论 → 改动思路（3 行以内）→ 唯一的 ```html 完整代码块 → 如果还不行可以怎么排查（2 条）。
````

## 验收清单

- [ ] 它先给了诊断而不是直接丢代码
- [ ] 改动范围确实很小
- [ ] 原功能与数据都保留
- [ ] 同一问题的备选方案也有给出

## 常见报错对照（可直接粘贴追问）

| 报错 | 大概率原因 | 补充追问 |
| --- | --- | --- |
| `xxx is not defined` | 函数名拼错或定义在作用域外 | 「检查每个函数是否在使用前已定义，改成先定义后调用」 |
| `Cannot read properties of null` | DOM 查询在元素渲染前执行 | 「把所有 DOM 查询与事件绑定移到 DOMContentLoaded 之后」 |
| `Unexpected token '<'` | 行内 JS 里出现了未转义的 `<` 或 `</script>` | 「检查内联 JS 字符串里是否含有 `</script>`，改为 `<\/script>`」 |
| `echarts is not defined` | CDN 加载失败 | 「加 onerror 降级为原生表格」 |
| `Failed to execute 'toDataURL'` | 图片跨域污染画布 | 「图片改用本地上传，不使用跨域 URL」 |

## 配套追问

1. 「先只告诉我哪几行有问题，先别输出代码」
2. 「在这个修复基础上顺便加移动端适配」
