# 功能扩展追加（追问专用）

> 在不破坏已有功能的前提下加新特性，一次加一个

## 占位符说明

| 占位符 | 含义 | 示例 |
| --- | --- | --- |
| `{{新功能}}` | 想加什么 | 「给记账本加预算提醒」 |
| `{{集成方式}}` | 放哪 | 「在设置面板里加一个开关」 |

## 用法

一次只加一个功能。想加多个就串行追问，成功率远高于一次提一堆。

## 提示词（中文版）

````text
在现有功能全部保留的前提下，给这个网页应用增加一个新功能。

【要增加的功能】
{{新功能}}

【希望集成的位置/方式】
{{集成方式}}

【现有代码】
{{原代码}}

【改动要求】
1. 先说明这个新功能会涉及哪些改动点：需要新增哪些状态字段、新增哪些 UI 元素、会不会影响现有数据流。
2. 向后兼容：新增的 localStorage 字段必须能在读取旧数据时正常工作——读取时用「取不到就用默认值」的合并策略（例如 Object.assign(默认值, 已存值)），保证老用户升级后不会出现 undefined 崩溃。
3. 最小侵入：优先在现有结构上追加，不重构无关的现有代码；如果确实需要改动现有函数，要在改动清单里说明原因。
4. UI 一致性：新功能沿用页面已有的配色、圆角、间距与交互反馈风格，看起来像同一套设计。
5. 边界处理：新功能同样要有空状态、输入校验与失败提示。
6. 输出完整 index.html（禁止省略号），代码块后用列表说明「新增了什么」与「改动了什么」。

【约束】
保持单文件内联；保持零第三方依赖（或维持原有国内 CDN）；界面保持中文；移动端响应式不被破坏；不要顺手删掉你觉得多余的功能。

【如果这个功能不适配】
如果这个功能在「无后端单文件」的架构下无法实现（例如需要真实的账号登录、多人实时同步、推送通知到手机），请直接说明不可行并给出 1-2 个可落地的替代方案，不要假装实现了。

【输出格式】
改动说明（3-5 条）→ 唯一的 ```html 完整代码块 → 新增功能怎么用（2 行）。
````

## 验收清单

- [ ] 旧数据打开后不报错（向后兼容生效）
- [ ] 新功能视觉风格与原有页面一致
- [ ] 原有功能没有被悄悄删掉
- [ ] 有一次只加了一个功能

## 不适合在单文件里做的功能（提前排雷）

| 诉求 | 为什么不行 | 可落地的替代 |
| --- | --- | --- |
| 真实注册登录 | 没有服务端，前端校验可被绕过 | 本地昵称切换 + 数据分区 |
| 多人实时同步 | 需要服务端与 WebSocket | 导出 JSON 互相导入 |
| 手机推送通知 | 需要后端推送通道 | 页面内倒计时 + Web Notification（需保持打开） |
| 支付 | 需要商户资质与回调 | 展示收款二维码图片（用户自传） |
| 云存储备份 | 需要账号体系 | 定期导出文件手动备份 |

## 配套追问
