## 3. 实测踩到的坑（已回填）

### 坑一：胜负判定未校验传入坐标（已补进 06-04）

照提示词写「以落子点为中心向两侧延伸计数」时，第一版没有做入口防御：

```js
// 缺这行 → 传入空点也会「判胜」
if (out of bounds || board[y][x] !== color) return false;
```

原因是左右两个方向会各自独立数到 >= 5，中间隔着什么并不知道。
已在中英双语提示词里补上防御要求，并附了 7 条必须自测的用例清单。

### 坑二：QUOTA 类型的 localStorage 异常会被静默吞掉

多个提示词（03-03 错题本、05-02 作品集、07-02 JSON）都涉及大对象存储。
原约束只写了「接近上限给提示」，实测更可靠的做法是 try/catch 包住写入并显式提示

```js
try { localStorage.setItem(k, v); }
catch (e) { /* QuotaExceededError：明确提示导出备份，不要静默失败 */ }
```

已在 05-02 中写明此要求。

## 5. 建议你上手后的回填动作

生成完一个应用，把源码丢给 IDE 搜这几串，命中即说明约束被突破：

```
jsdelivr | unpkg | cdnjs        → 违反 CDN 约束
Math.random()                    → 密码生成类违反安全约束
eval( | new Function(           → JSON 解析类违反安全约束
innerHTML = ... + 用户输入       → 缺少转义，有 XSS 风险
fetch( | XMLHttpRequest         → 声称离线的页面仍有网络请求
```

搜到就对着 `prompts/08-通用增强/03-修复报错.md` 或 `05-离线单文件打包.md` 追问一次，通常一轮能修好。
