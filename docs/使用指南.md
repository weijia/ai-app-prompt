# 使用指南 · 如何在豆包 / 元宝里稳定生成网页应用

## 1. 基本流程

```
挑提示词 → 替换 {{占位符}} → 整段复制 → 粘贴到对话框 → 发送
→ 得到 index.html 代码块 → 复制代码 → 新建文本文档粘贴
→ 重命名为 index.html（注意后缀必须是 .html 不是 .html.txt）→ 双击浏览器打开
```

> Windows 常见坑：资源管理器默认「隐藏已知文件扩展名」，重命名成 `xxx.html.txt` 会导致打不开。
> 解决办法：资源管理器 → 查看 → 勾选「文件扩展名」；或用 VS Code 保存。

## 2. 三个能显著提升成功率的技巧

### 技巧一：占位符一定要填，别留空

`{{这里}}` 留着不填，模型会自由发挥，结果通常跑偏。哪怕只填一句「给我女儿用的小学生口算练习」也比空着好。

### 技巧二：一次只要一个应用

不要说「再顺便加个登录和评论区」。没有后端的单文件应用做不了真登录。想要额外功能，生成后用 [08-通用增强/04-功能扩展追加](../prompts/08-通用增强/04-功能扩展追加.md) 追问。

### 技巧三：结果不理想，先诊断再重试

| 症状 | 处理 |
| --- | --- |
| 代码被截断、出现「……」省略 | 追问：「请从第 N 行继续，输出剩余完整代码」，或改用「精简模式」重新生成 |
| 页面白屏 | 打开 F12 控制台，把红色报错贴回去（见 [03-修复报错](../prompts/08-通用增强/03-修复报错.md)） |
| 样式全丢、像纯文本 | CDN 加载失败，用 [05-离线单文件打包](../prompts/08-通用增强/05-离线单文件打包.md) 让它去掉 CDN |
| 手机上一团乱 | 用 [01-移动端适配](../prompts/08-通用增强/01-移动端适配.md) 追问 |
| 功能对但很丑 | 用 [02-视觉美化升级](../prompts/08-通用增强/02-视觉美化升级.md) 追问，并指定风格 |
| 刷新后数据丢失 | 追问：「把所有数据改为 localStorage 持久化，并加导出导入 JSON 按钮」 |

## 3. 迭代式用法（推荐）

第一次对话只求「跑起来」，后面用追问逐步加料，比一次性提大需求成功率高得多：

```
第 1 轮：基础提示词 → 能运行的最小版本
第 2 轮：移动端适配 → 手机上能正常用
第 3 轮：视觉美化 → 指定配色与风格
第 4 轮：功能追加 → 一次加 1 个特性
第 5 轮：离线打包 → 去掉 CDN，存档或分享
```

## 4. 上下文长度注意事项

豆包 / 元宝有单次输出长度上限。**越复杂的应用越容易在生成中途被截断**。
应对办法：

- 让它先输出「只含布局骨架、不含业务逻辑」的版本，确认后再让它补逻辑；
- 或明确要求「不超过 400 行，功能保留核心三项」；
- 也可以使用 [00-通用基座/01-万能网页应用生成器](../prompts/00-通用基座/01-万能网页应用生成器.md) 里的「精简模式」参数。

## 5. 安全与隐私提醒

- 提示词里已要求金额、密码等敏感计算**在前端本地完成，不上传网络**。
- 不要粘贴真实身份证号、银行卡号、密钥等数据到对话框。
- 生成的页面若被分享出去，`localStorage` 数据只存在分享者自己的浏览器里，不会外泄。
